# 校园汇 · 校园活动发布与报名管理平台

依据《校园活动发布与报名管理平台 项目设计文档 V1.0》实现的 Web 课程项目。使用 React、Vite、React Router、CSS3、ECharts，采用 localStorage 本地持久化。

## 启动

要求 Node.js 20.19+ 或 22.12+。在本目录终端执行：

```powershell
npm.cmd install
npm.cmd run dev
```

访问终端显示的地址，默认 http://127.0.0.1:5173 。这是 React 应用，请通过开发服务器运行，不要直接双击 index.html。

## 已实现

- 学生端：首页、活动广场、关键词搜索、分类与状态筛选、三种排序、分页、活动详情、报名确认、取消与重新报名、报名状态与审核备注、个人资料。
- 身份模块：登录、学生注册、退出、角色路由守卫、服务层权限校验、密码加盐 PBKDF2 派生存储。
- 管理端：数据看板、活动新建与编辑、草稿、发布、下架、逻辑删除、报名通过与拒绝、审核备注、CSV 名单导出、用户查询、数据统计。
- 图表：分类环形图、可切换周期的报名趋势、热门活动排行、报名处理分布。数据均从本地实体计算。
- 交互：字段错误提示、Toast、关键操作确认、空状态、404、无权限页面、损坏数据恢复、移动端导航与响应式布局。

## 业务规则

1. 待审核与已通过均占名额；拒绝与取消不占名额。
2. 同一学生对同一活动不能重复拥有有效报名，可在取消或拒绝后重新申请。
3. 草稿不公开；截止、满额、下架、进行中、已结束与已删除活动不允许新报名。
4. 活动开始前可以取消本人有效报名；开始后无法取消或继续审核。
5. 缩减容量不能低于当前有效报名人数。
6. 删除活动保留实体和历史报名，移除公开与管理列表，禁止后续审核。
7. 页面每 30 秒更新一次时间状态；业务操作执行时重新校验实际时间和最新本地数据。同浏览器其他标签页的变更通过 storage 事件同步。

## 演示顺序

1. 游客浏览首页，在活动广场搜索“人工智能”。
2. 使用 20260001 登录，打开活动并提交报名，刷新验证持久化。
3. 切换 admin，在报名管理中搜索 20260001，通过申请。
4. 切回学生，在“我的报名”查看已通过状态，可演示取消。
5. 管理员发布新活动、编辑、上下架，查看数据统计与名单导出。

“个人中心 → 演示数据管理”可确认恢复初始数据，会覆盖本地修改并退出当前账号。不要在真实数据上使用恢复操作。

## 项目结构

```text
src/
  components/          通用 UI、活动海报与图表
  context/             全局数据、会话、提示与确认弹窗
  data/                演示数据与分类
  layouts/             学生端与管理员端布局
  pages/auth/          登录和注册
  pages/student/       首页、广场、详情、报名、资料
  pages/admin/         看板、活动、审核、用户、统计
  services/platform.js 集中业务规则与权限检查
  styles/              桌面、平板、手机样式
  utils/               存储事务、日期、CSV 导出
tests/                 业务测试与浏览器流程测试
```

## 验证与打包

```powershell
npm.cmd test
npm.cmd run test:e2e
npm.cmd run build
npm.cmd run preview
```

浏览器测试默认使用本机 Microsoft Edge 的无头模式。若未安装 Edge，可将 playwright.config.js 的 channel 改为 chrome，或安装 Playwright Chromium 后删除 channel 设置。

构建产物在 dist。部署到静态服务器时，需要将未命中的页面路径回退到 index.html，以支持 React Router 的直接访问。

## 当前版本边界

这是设计文档要求的单浏览器前端课程原型，无后端、共享数据库与跨设备同步。账号与角色校验仅用于演示，不能作为生产系统的安全边界。请使用演示资料；正式上线需接入后端身份认证、数据库及服务端权限与名额校验。当前未实现禁用账号操作、真实通知、签到、评论等后续扩展。
